# Token economy survey for nyla

## Purpose

Static rules live in `CLAUDE.md` "Token economy" section. This skill = methodology to *find new* rules and propose CLAUDE.md edits. Sister to `cleanup` (which fixes code slop). Cleanup = code domain. This skill = agent-read-pattern domain.

## Posture

- Surface findings, don't apply silently. CLAUDE.md edits need user sign-off.
- Rules go in CLAUDE.md, not here. Skill is the *finder*, CLAUDE.md is the *enforcer*.
- One-line tripwires only. Posture-shaped, not checklist.
- Don't propose what's already covered. Read CLAUDE.md "Token economy" first.

## Tripwire categories

Recurring sources of wasted tokens:

### 1. Vendored / generated headers read whole

Big files copy-pasted from upstream (stb, Khronos, RenderDoc SDK). Agents read whole when `grep -n <symbol>` would do. Never edited.

Find: `find nyla/commons -type f \( -name '*.h' -o -name '*.cc' \) -exec wc -l {} + | sort -rn | head -20` — anything >500 LOC + has upstream-copyright header = candidate.

### 2. Generated index/list files

Schema dumps, asset index headers, anything produced by a script. Re-run script + grep to verify; never read whole.

Find: `grep -rln 'AUTO-GENERATED\|DO NOT EDIT\|generated by' nyla/`.

### 3. Auto-loaded context bloat

Files Claude reads on every session start: `CLAUDE.md`, `ITERATION.md`, `MEMORY.md` index, available skill list. Each line = persistent token cost.

Audit: `wc -l CLAUDE.md ITERATION.md` — caps: CLAUDE.md ~100, ITERATION.md ~80 (per its own rule). MEMORY.md index lines >150 chars = trim.

### 4. Stale or redundant skills

Skill `description` field auto-loads on every session. Stale skills = noise.

Audit: list skills, eyeball descriptions for overlap, ask user before deleting.

### 5. Files where `grep` would suffice

Pattern: agent reads `foo.h` whole to find one function. Tripwire if file >300 LOC and used as lookup target.

Find by tracking session transcripts for repeated full-reads of same file.

### 6. Both .h and .cc when one suffices

Agents tend to read pair when only one needed. Tripwire only when measurable — usually fine since wrappers are thin.

## Survey methodology

When invoked explicitly:

1. `wc -l` over `nyla/commons/`, repo root apps, `assets/`, `asset_public/`. List top 15.
2. For each >500 LOC file: classify (vendored / generated / first-party). Vendored/generated = candidate.
3. Cross-check against existing CLAUDE.md "Token economy" — skip already-covered.
4. `wc -l CLAUDE.md ITERATION.md` + line-length scan of MEMORY.md index. Flag oversize.
5. List skills, scan descriptions for overlap.
6. Propose concrete CLAUDE.md edits as one-line tripwires, posture-shaped. Surface to user, don't apply.

## When auto-triggering

If during ordinary work you read a vendored/generated/big file whole + realize grep would have done — surface as proposed CLAUDE.md addition at end of turn. Don't refactor on the fly.

## Out of scope

- Code-slop fixes — that's the `cleanup` skill.
- Reformatting CLAUDE.md / ITERATION.md beyond the rule additions you propose.
- Editing vendored/generated files.
- Caching / runtime perf — token-econ = agent input cost, not runtime cost.
